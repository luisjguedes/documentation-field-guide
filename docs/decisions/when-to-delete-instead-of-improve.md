# When to delete instead of improve documentation

## The decision
Should you fix a weak page — or remove it entirely?

## The uncomfortable truth
Most bad documentation is not *wrong*.  
It’s **confident, fluent, and irrelevant**.

Improving it often makes it worse.

## Signals a page should be deleted
- It explains *what* without enabling *action*
- It restates what the UI already shows
- It exists only because “we should document this”
- It hasn’t been referenced in months
- No one can articulate its primary user

## My default
If a page does not:
- change a decision
- unblock a task
- prevent a known failure

…it gets deleted.

## Why deletion is a senior skill
- It preserves trust
- It reduces maintenance surface
- It forces sharper future writing

## Replacement rule
Only replace deleted content if you can replace it with:
- a step
- a constraint
- a warning
- an example
- a measurable outcome

Otherwise, leave the gap.
