# Style guide conflicts: Google vs Microsoft vs Chicago

## The decision
When authoritative style guides disagree, which one do you follow — and why?

This is not a theoretical problem. It shows up immediately in capitalization, sentence structure, UI labels, terminology, and tone.

## The options

### A) Follow the product’s primary style guide
**Pros**
- Internal consistency
- Easier onboarding for contributors
- Fewer review debates

**Cons**
- May clash with audience expectations
- May inherit blind spots from the chosen guide

### B) Follow the audience’s expectations
**Pros**
- Reduces cognitive friction
- Aligns with existing mental models

**Cons**
- Can fragment your doc set
- Harder to enforce at scale

### C) Follow local consistency inside the doc set
**Pros**
- Readers adapt quickly to internal patterns
- Reduces stylistic churn

**Cons**
- Requires active editorial oversight
- Can drift without governance

## My default
**Pick one primary guide, but treat it as a baseline — not a law.**  
Then optimize locally for clarity and audience fit.

## When I override the default
- External developer audiences with strong conventions
- UI text where product language already contradicts the guide
- Legacy docs where changing tone would be more disruptive than helpful

## Quick checklist
- Does this choice reduce reader friction?
- Will a new contributor understand the rule?
- Is this deviation intentional and documented?
