# Ownership models that don’t rot

## The decision
Who owns documentation after it ships?

Lack of ownership is the fastest path to doc decay.

## Common models

### Single DRI
One named owner per page or area.

**Works when**
- Scope is stable
- Team size is small

**Fails when**
- Owners change roles frequently

### Docs follow the code
The code owner owns the docs.

**Works when**
- Engineers accept documentation as part of delivery
- Review culture is strong

**Fails when**
- Docs are treated as optional

### Rotating editor
Editorial responsibility rotates.

**Works when**
- Team maturity is high
- Scope is well defined

**Fails when**
- Rotation becomes symbolic

### Doc council
Group oversight.

**Works when**
- Used sparingly
- Focused on standards, not approvals

**Fails when**
- It becomes a gate

## My default
**Docs follow the code**, with a writer as facilitator and quality owner.

## Failure modes to watch
- “Everyone owns it” → no one owns it
- Ownership without authority
- Ownership without review time

## Checklist
- Is an owner named?
- Can the owner say “no”?
- Is ownership visible in the page?
